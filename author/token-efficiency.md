# Token efficiency (author)

Fitness bar for disclosure: small asks stay small. Not a visitor feature.

## Rules of thumb

1. Read skill **descriptions** only, then at most one matching body (plus constitution when the Always-on summary is not enough). Never preload every `SKILL.md`.
2. Copy-only, flow-only, IA-only, and evidence-only asks must not start the design pipeline.
3. Choice and Confirmation: constitution only. Other skills one-line point.
4. `SKILL.md` = executable rules. Do not pad with essays or restated Choice specs.

## Measure fixtures

Disclosure checks (which skills should load). Do not start a nested design-pipeline session with the Atlas author as the product client.

### A — Tiny copy

Prompt: `Rename the primary button on the save dialog to "Save changes".`

**Pass:** UX Writing (and constitution only if implementing).  
**Fail:** design pipeline, evidence, user-flow, or IA bodies loaded for the ask.

### B — Structure only

Prompt: `Map the happy path for canceling a pending invite. Do not design the screen.`

**Pass:** user-flow (IA only if places are in scope).  
**Fail:** design pipeline started.

### C — Full design

Prompt: `Design how an existing customer cancels a paid subscription in our web app.`

**Pass:** design pipeline. Guided is the default. Express only if the partner asks (e.g. "you decide").
